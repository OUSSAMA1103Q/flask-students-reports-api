# Students & Reports REST API

A small REST API built with **Flask** that manages students and the reports they write. Data is stored in plain **Python lists** of dictionaries (no database). Authentication uses JSON Web Tokens generated and verified with **PyJWT**, and every endpoint was tested with **Postman**. Every response, including errors, is JSON.

## Data model

**Student**

| Field | Description |
|---|---|
| `ID_S` | Student id (generated by the server) |
| `FN` | First name |
| `LN` | Last name |
| `Diplome` | `0` or `1` |
| `Level` | Study level (e.g. "Master 1") |
| `report_id` | Id of the report the student belongs to |

**Report**

| Field | Description |
|---|---|
| `ID_R` | Report id (generated by the server) |
| `Title` | Title |
| `Type` | Report type (e.g. "Internship") |
| `K1`, `K2`, `K3` | Three keywords |
| `Release_Date` | Date in `YYYY-MM-DD` format |

**Relationship:** Student (1,1) — (1,2) Report

- Each student is linked to exactly one report (`report_id` must point to an existing report).
- A report has **at most 2 students**. Adding a third returns `409 Conflict`.
- A report that still has students linked to it **cannot be deleted** (`409 Conflict`).

IDs are always generated by the server (highest existing id + 1). All fields are required in `POST` and `PUT` request bodies.

## Endpoints

Base URL: `http://127.0.0.1:5000`

| Method | URL | Token needed | Success | Possible errors |
|---|---|---|---|---|
| GET | `/` | No | 200 | – |
| POST | `/login` | No | 200 | 400, 401 |
| POST | `/refresh` | No (refresh token in body) | 200 | 400, 401 |
| GET | `/students` | **Yes** (access) | 200 | 401 |
| GET | `/students/<id>` | **Yes** (access) | 200 | 401, 404 |
| POST | `/students` | No | 201 | 400, 404 (report not found), 409 (report already has 2 students) |
| PUT | `/students/<id>` | No | 200 | 400, 404 (student or report not found), 409 (report already has 2 students) |
| DELETE | `/students/<id>` | No | 200 | 404 |
| GET | `/reports` | No | 200 | – |
| GET | `/reports/<id>` | No | 200 | 404 |
| POST | `/reports` | No | 201 | 400 |
| PUT | `/reports/<id>` | No | 200 | 400, 404 |
| DELETE | `/reports/<id>` | No | 200 | 404, 409 (students still linked) |

Any of these URLs called with a method it doesn't support returns `405`.

## Authentication

1. **Log in:** `POST /login` with

   ```json
   { "username": "admin", "password": "test123456" }
   ```

   The response contains two tokens:
   - `access_token`, valid for **15 minutes**, used to call protected endpoints
   - `refresh_token`, valid for **7 days**, used only to get a new access token

2. **Call a protected endpoint** by sending the access token in the header:

   ```
   Authorization: Bearer <access_token>
   ```

3. **Refresh:** when the access token expires, call `POST /refresh` with

   ```json
   { "refresh_token": "<refresh_token>" }
   ```

   and you get a new `access_token`.

Each token's payload has a `"type"` field (`"access"` or `"refresh"`). Because of this, the two tokens can't be swapped: a refresh token is rejected on protected endpoints, and an access token is rejected by `/refresh` (`401`).

Protection is implemented with a `@token_required` decorator. It checks the `Authorization` header, the signature, the expiration and the token type. It is applied to the student read endpoints (`GET /students` and `GET /students/<id>`).

## Error handling

Every error is returned in the same JSON format:

```json
{
  "error": "Not Found",
  "message": "Student with id 99 not found",
  "status": 404
}
```

| Code | When |
|---|---|
| 400 Bad Request | Body is not valid JSON, a required field is missing, `Diplome` is not 0/1, `report_id` is not an integer, or `Release_Date` is not a real `YYYY-MM-DD` date |
| 401 Unauthorized | Wrong username/password, or a token that is missing, invalid, expired, or of the wrong type |
| 404 Not Found | Student or report id does not exist |
| 405 Method Not Allowed | HTTP method not supported on that URL |
| 409 Conflict | Report already has 2 students, or deleting a report that still has students |
| 500 Internal Server Error | Any unexpected error (details are logged on the server, not sent to the client) |

## How to run

Requires Python 3.

```bash
# 1. Create and activate a virtual environment
python -m venv .venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # macOS / Linux

# 2. Install the dependencies
pip install -r requirements.txt

# 3. Start the server
python app.py
```

The API runs at `http://127.0.0.1:5000`.

## How to test

1. Start the server (`python app.py`).
2. In Postman, click **Import** and select `postman/collections/Flask_API.postman_collection.json`.
3. Open the collection and click **Run collection**. It runs all **29 requests** in order (login, protected routes, CRUD on students and reports, and the error cases).

## Run with Docker

The API is containerized with a `Dockerfile` (python:3.12-slim + gunicorn) and a `docker-compose.yml`. The container runs `app1.py` and exposes port `5000`. Once it is up, the API is available at `http://127.0.0.1:5000`.

The image is published on Docker Hub: **https://hub.docker.com/r/boughdiri/flask-students-reports-api**

### Run from Docker Hub (quickest — no need to clone)

```bash
docker pull boughdiri/flask-students-reports-api:latest
docker run -d -p 5000:5000 boughdiri/flask-students-reports-api:latest
```

Then open **http://127.0.0.1:5000/student** in a browser.

### Run from source (with Docker Compose)

```bash
# Build the image and start the container in the background
docker compose up -d --build

# Follow the logs (Ctrl+C to stop following)
docker compose logs -f api

# Stop and remove the container
docker compose down
```

## Notes

- Data is kept **in memory**: any change is lost when the server restarts, and the sample data comes back.
- To keep the assignment simple, the secret key and the user's password are written directly in `app.py`. In a real project they would be stored in **environment variables** and the password would be hashed.
